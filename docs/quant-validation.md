# KQ Quant Tool — 퀀트 검증 규칙

이 문서는 퀀트 프로젝트 특화 검증 규칙을 정의한다.
모든 백테스트, 시그널 생성, 모델 학습은 이 규칙을 통과해야 한다.

---

## 1. 데이터 누수 방지 (Look-ahead Bias)

### 1.1 시그널 계산
- ❌ T일 종가로 신호 생성 + T일 종가로 체결
- ✅ T일 종가로 신호 → T+1일 시가로 체결
- ✅ 또는 T일 종가로 신호 → T+1일 종가로 체결 (명시 필요)

### 1.2 재무 데이터 시점
- ❌ 1분기 재무 (3/31 기준) 데이터를 1분기 동안 사용
- ✅ 1분기 재무 → 공시 후 4월 말 이후부터 사용
- ✅ FnGuide 데이터는 공시 지연 반영됨 (확인 필요)

### 1.3 매크로 데이터 시점
- ❌ Q1 GDP를 Q1 동안 알고 있다고 가정
- ✅ Q1 GDP는 Q2 중반 이후 발표 → 그때부터 사용
- ⚠️ 현재 코드는 quarter end 기준 → 발표 지연 미반영 (개선 여지)

### 1.4 모델 학습
- ❌ 전체 데이터로 학습 후 일부 구간 테스트
- ✅ 시간순 분할: 학습(2014~2022) / 검증(2023~2024) / 테스트(2025~)
- ✅ 또는 walk-forward validation

## 2. 백테스트 정확성

### 2.1 거래 비용
- 수수료: 한국 주식 기본 0.015% (편도)
- 슬리피지: 보수적 0.1% (편도)
- 세금: 매도 시 0.18% (거래세) — 현재 미반영
- 백테스트 결과에 비용 차감 여부 명시

### 2.2 체결 가격
- 시그널 = T일 종가 기준
- 체결 = T+1일 시가 (기본)
- 동일 봉 신호+체결 금지

### 2.3 리밸런싱
- 리밸런싱 날짜 vs 실제 거래 날짜 구분
- 월말 리밸런싱 → 다음 영업일 거래
- 거래정지 종목 → 다음 영업일로 연기

### 2.4 종목 풀
- 시점 t에 상장된 종목만 사용
- 상장폐지 종목 포함 (생존편향 방지)
- 신규 상장 종목 → 상장일 이후만 사용

### 2.5 비교 벤치마크
- KOSPI 지수와 동일 기간 비교
- 동일 리밸런싱 가정 (배당 재투자 등)
- 알파 = 전략수익률 - 베타 × 벤치마크수익률

---

## 3. 모델 검증

### 3.1 표본 크기 vs 모델 복잡도

| 데이터 단위 | 표본 크기 | 적합 모델 |
|---|---|---|
| 분기 매크로 | 49 | TabPFN, LightGBM (얕은), 규칙 기반 |
| 월간 종목 | ~250 | LightGBM, XGBoost |
| 일간 종목 | ~3,000 | 거의 모든 모델 |
| 분 단위 | ~수만 | 딥러닝 가능 |

**금지**: 표본 < 100인데 딥러닝 (LSTM 등) 사용

### 3.2 과적합 검증
- 학습 정확도 vs 검증 정확도 격차 < 10%p
- Cross-validation 결과 보고
- 백테스트 Sharpe > 3 이면 과적합 의심

### 3.3 비현실적 결과 검토
다음 결과는 모두 데이터 누수 또는 버그 의심:
- 연 수익률 > 100%
- Sharpe ratio > 5
- 최대 낙폭 < 5%
- 승률 > 90%
- 알파 > 50%p

이런 결과 나오면 **반드시 원인 파악 후 PRD에 기록**

### 3.4 통계적 유의성
- 백테스트 결과에 신뢰구간 표기
- 표본 50개 이하면 p-value 보고
- 우연 vs 진짜 알파 구분

## 4. Alpha Decay 측정

### 4.1 정의
- 시그널 발생 후 시간 경과에 따른 평균 수익률 감쇠
- 반감기 t½ = ln(2) / λ (지수감쇠 가정)

### 4.2 측정 방법
- 시그널 발생 시점 t
- t+1, t+3, t+5, t+7, t+10, t+15, t+20일 수익률
- 평균 수익률 곡선 → 지수감쇠 피팅

### 4.3 국면별 측정 (확장)
- 동일 시그널이라도 국면에 따라 t½ 다름
- 골디락스 RSI 과매도 vs 디플레이션 RSI 과매도
- 각 국면별 충분한 시그널 수 확인 (최소 30회 권장)

### 4.4 신호 신뢰도 가중
- 반감기 짧음 → 빠른 청산 필요
- 반감기 김 → 길게 보유 가능
- 자산배분에 반영 시 명시

---

## 5. 자산배분 검증

### 5.1 위험기반 배분 (GMV/MDP/ERC)
- 공분산 행렬 정확성 검증
- 최소 60일 이상 데이터 필요
- ETF 데이터 동일 길이 보장

### 5.2 정적 배분 (영구포트폴리오 등)
- 비중 합계 = 1.0 (±0.01)
- 음수 비중 (공매도) 의도적인지 확인
- 비중 변경 시 거래 비용 반영

### 5.3 동적 배분
- 리밸런싱 빈도 vs 거래 비용 트레이드오프
- 분기 리밸런싱 권장 (월간은 비용 부담)

## 6. AI 모델 특화 검증

### 6.1 LightGBM
- `num_leaves` < 표본/100 (과적합 방지)
- `min_child_samples` 충분히 크게
- early stopping 사용

### 6.2 TabPFN
- 표본 < 10,000인 경우만 사용
- 사전훈련된 모델이라 추가 학습 안 됨 → 입력 피처 정규화 확인

### 6.3 HMM
- Hidden state 수 = 사전 정의된 국면 수 (4)
- 학습 데이터에 모든 국면 출현 확인
- 전환 확률 행렬 합 = 1.0 (각 행)

## 7. UI 검증

### 7.1 가격 일관성
- 차트 가격과 헤더 가격 단위 일치
- 수정종가 / 실제종가 혼용 금지
- 표시 형식 통일 (천 단위 콤마, 통화 단위)

### 7.2 데이터 시점 표시
- "실시간" vs "2026-06-05 종가" 명시
- 사용자가 혼동하지 않도록

### 7.3 신뢰도 표시
- 확률 / 점수 / 등급 항상 표시
- 0~100% 또는 0~10 명확히
- 신뢰도 낮을 때 경고 표시

## 8. 발표 대비 검증

### 8.1 예상 질문 리스트
모든 PRD에 다음 질문에 대한 답변 준비:

**데이터 관련**:
- "데이터 출처는 어디?"
- "데이터 누수는 어떻게 방지했나?"
- "상장폐지 종목은 어떻게 처리?"

**모델 관련**:
- "왜 이 알고리즘?"
- "왜 다른 알고리즘은 안 썼나?"
- "과적합 검증은?"

**결과 관련**:
- "백테스트 결과가 너무 좋은데 데이터 누수 아닌가?"
- "실제 시장에서도 동작할까?"
- "벤치마크 대비 통계적 유의성은?"

### 8.2 시연 안정성
- 외부 API 없이도 핵심 기능 동작
- 모든 캐시 미리 생성
- 시연 PC에서 사전 리허설

### 8.3 코드 재현성
- 다른 사람이 코드 받아서 30분 안에 동일 결과 재현 가능
- README에 환경 설정 명시
- 데이터 파일 위치 / 형식 명확

---

## 9. 체크리스트 (모든 백테스트 / 모델 결과 검증)

새 백테스트 또는 모델 결과 만들 때마다:

- [ ] 시그널 발생 시점 명시 (T일 종가)
- [ ] 체결 시점 명시 (T+1일 시가 등)
- [ ] 거래 비용 반영 (수수료 + 슬리피지)
- [ ] 상장폐지 종목 포함 여부 명시
- [ ] 결측치 처리 방법 명시
- [ ] 학습 / 검증 / 테스트 분리 명시
- [ ] 결과가 비현실적이지 않은가 확인
- [ ] 벤치마크 동일 기간 비교
- [ ] 통계적 유의성 검토
- [ ] 발표 시 예상 질문에 답변 가능

---

## 10. 위반 시 행동

이 규칙을 위반한 결과가 발견되면:

1. **즉시 결과 사용 중단**
2. **원인 파악**: 어느 규칙 위반인지 명시
3. **수정 작업**: PRD/Task로 등록
4. **재검증**: 수정 후 동일 검증 통과 확인
5. **문서화**: Implementation Notes에 기록

특히 **발표 직전에 위반 발견 시**:
- 해당 결과 발표 자료에서 제외
- 또는 명확히 "검증 진행 중" 라벨 표시
- 절대 의도적 은폐 금지
