# Rule: Generating an Implementation Task List

## Goal

PRD를 분석해 구현 가능한 작은 작업으로 분해한다.

## When to Use

PRD가 작성되고 승인된 후, 본격 구현 들어가기 전에 사용한다.

## Process

1. 지정된 PRD를 읽는다.
2. 현재 프로젝트 구조와 기존 코드를 확인한다.
3. 변경하거나 생성할 파일을 식별한다.
4. 먼저 상위 작업을 작성한다.
5. 사용자에게 상위 작업 확인 요청한다.
6. 승인 후 각 상위 작업을 작은 하위 작업으로 분해한다.
7. 결과를 `tasks/tasks-[prd-file-name].md`로 저장한다.

## Task Requirements

각 작업은 다음 조건을 만족해야 한다.

- **하나의 명확한 목적만 가진다.**
- 완료 여부를 객관적으로 판단할 수 있다.
- 가능한 한 독립적으로 테스트할 수 있다.
- 선행 작업과 의존 관계를 반영한다.
- 구현 작업과 테스트 작업을 포함한다.
- 너무 큰 작업은 더 작은 단위로 분리한다.
- **30분 ~ 2시간 이내에 완료 가능한 크기**

## Output Format

```markdown
# Tasks: [Feature Name]

PRD: `tasks/prd-[feature-name].md`
생성일: YYYY-MM-DD

## 관련 파일 (Relevant Files)

### 기존 파일 (수정)
- `path/to/file.py` — 변경 내용 요약
- `tests/test_file.py` — 테스트 파일의 역할

### 새 파일 (생성)
- `path/to/new_file.py` — 파일의 역할

### 사용자 PC 환경 변경 (있는 경우)
- `pip install xxx` — 사유

## Tasks

### [ ] Task 1: 사전 준비
- [ ] 1.1 ...
- [ ] 1.2 ...

**완료 기준**: 명확히 검증 가능한 조건

**테스트**:
```bash
명령어
```

### [ ] Task 2: 백엔드 구현
...

### [ ] Task 3: API 엔드포인트
...

### [ ] Task 4: 프론트엔드 UI
...

### [ ] Task 5: 통합 테스트
...

## Important Rules

작업 진행 시 지켜야 할 규칙:

1. 한 번에 하나의 Task만 진행
2. 각 Task 완료 후 사용자 테스트
3. 기존 인터페이스 변경 금지
4. 요청 안 한 리팩터링 금지
5. 실패하면 해당 작업만 롤백
6. 변경 사항을 Implementation Notes에 기록

## Implementation Notes (구현 기록)

### Task 1 (완료)
- 작성 파일: ...
- 테스트 결과: ...

### Task 2 ...

## 진행 상태

| Task | 상태 | 담당 |
|---|---|---|
| Task 1 | ⏳ 대기 | ... |
| Task 2 | ⏳ 대기 | ... |

## 다음 작업

다음에 진행할 Task와 사전 조건.
```

## Important Rules

- **PRD 범위를 벗어나는 기능을 추가하지 않는다.**
- 데이터베이스 / 큰 구조 변경은 별도 작업으로 만든다.
- 테스트를 마지막에 한꺼번에 만들지 않는다.
- 관련 구현 작업에 해당 테스트를 포함한다.
- 각 하위 작업은 가능한 한 작은 단위로 작성한다.
- 리팩터링과 신규 기능 구현을 하나의 작업에 섞지 않는다.
- 보안, 오류 처리, 문서화 작업을 누락하지 않는다.

## KQ Quant Tool 특화 규칙

### 백엔드 작업 시
- `server.py`는 단일 파일이므로 변경 위치 정확히 명시 (줄 번호)
- 기존 API 엔드포인트 영향 없는지 확인
- 모델 학습 시간 측정 (서버 시작 시간 영향)

### 프론트엔드 작업 시
- `index.html`은 단일 파일이므로 어느 `<div id="...">` 영역 수정인지 명시
- 기존 탭에 영향 없는지 확인
- JS 함수 시그니처 유지

### 데이터 작업 시
- 엑셀 → parquet 캐싱 전략 유지
- 컬럼명 변경 시 backward compatibility 고려

### 테스트 작업 시
- `python3 server.py` 시작 시 콘솔 로그 확인
- `curl http://127.0.0.1:8888/api/...` 응답 확인
- 브라우저에서 Ctrl+F5 후 시각 검증
