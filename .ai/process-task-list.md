# Rule: Processing a Task List

## Goal

작업 목록의 하위 작업을 한 번에 하나씩 안전하게 구현한다.

## When to Use

Task List가 작성되고 승인된 후, 실제 구현 단계에 사용한다.

## Process

각 Task마다 다음 순서로 진행한다:

1. Task List와 관련 PRD를 다시 읽는다.
2. 아직 완료되지 않은 **첫 번째 하위 작업**을 선택한다.
3. 관련 기존 코드와 테스트를 확인한다.
4. **구현 계획을 짧게 작성한다** (변경 위치, 영향 범위).
5. **사용자에게 계획 승인 요청.**
6. 선택한 작업만 구현한다.
7. 구문 검증 (`python3 -c "import ast; ast.parse(...)"` 등).
8. **사용자가 본인 PC에서 테스트하도록 안내.**
9. 사용자가 OK 확인 후 작업을 [x]로 표시.
10. Implementation Notes에 다음을 기록:
    - 변경한 파일 목록
    - 변경 내용 요약
    - 테스트 결과
    - 알려진 한계
11. 다음 작업으로 이동.

## Rules

### 절대 규칙
- **한 번에 하나의 하위 작업만 구현한다.**
- 요구받지 않은 리팩터링은 하지 않는다.
- 기존 공개 인터페이스를 임의로 변경하지 않는다.
- 테스트 실패 상태에서 다음 작업으로 넘어가지 않는다.
- 오류를 숨기거나 실패하는 테스트를 삭제하지 않는다.
- 임시 코드, 더미 데이터, 불필요한 하드코딩을 남기지 않는다.
- 새로운 패키지를 추가할 때는 이유를 기록한다.
- **파일 삭제, 폴더 변경, Git reset을 임의로 실행하지 않는다.**
- API 키, 비밀번호, 계좌정보를 코드에 저장하지 않는다.
- 완료 조건을 충족하지 못하면 작업을 완료 처리하지 않는다.

### KQ Quant Tool 특화 규칙

#### 파일 변경 규칙
- `server.py` 변경 시 → 구체적 함수명·라인 영역 명시
- `index.html` 변경 시 → 어느 `<div id="...">` 영역인지 명시
- `data_loader.py` 변경 시 → 캐시 무효화 필요한지 명시
- 새 파일 추가 시 → 어디에 import되는지 명시

#### 변경 후 검증 명령

**서버 동작 확인**:
```bash
# WSL 새 터미널에서
curl http://127.0.0.1:8888/api/ping
# {"ok": true} 응답 확인
```

**구문 검사 (적용 전)**:
```bash
python3 -c "import ast; ast.parse(open('server.py').read())"
python3 -c "import ast; ast.parse(open('data_loader.py').read())"
node -e "const fs=require('fs'); const html=fs.readFileSync('index.html','utf8'); const m=html.match(/<script>([\s\S]*)<\/script>/); new Function(m[1])"
```

**API 응답 확인**:
```bash
curl http://127.0.0.1:8888/api/<엔드포인트> | head -50
```

**브라우저 시각 검증**:
- 윈도우 브라우저에서 `http://localhost:8888` 접속
- Ctrl+F5 (강제 새로고침)
- 영향받은 탭 + 기존 다른 탭 모두 확인
- 화면 캡처로 확인

#### 데이터 누수 방지 (퀀트 특화)
- 시그널 계산 시 미래 데이터 사용 금지
- 백테스트 결과가 비현실적으로 좋으면 데이터 누수 의심
- 학습/검증 분리 명시
- 상장폐지 종목 처리 방법 기록

## Completion Record (작업 완료 후 기록)

각 Task 완료 시 Task List 파일의 Implementation Notes에 다음 추가:

```markdown
### Task X (완료)
- **변경 파일**: file1.py (1~50줄), file2.html (#panel-xxx 영역)
- **변경 내용**: 한 줄 요약
- **추가 의존성**: pip install ... (있으면)
- **검증 명령**:
  - `python3 -c "..."` → OK
  - `curl ...` → 응답 OK
  - 브라우저 검증 → 사용자 확인
- **알려진 한계**: ... (있으면)
- **후속 작업**: ... (있으면)
```

## Rollback (실패 시 복구)

작업 실패 시:

1. **변경한 파일만 롤백** (다른 작업 결과는 보존)
2. 어디서 실패했는지 Implementation Notes에 기록
3. 원인 파악 후 다시 시도하거나 작업 분해
4. **절대 여러 작업을 한 번에 되돌리지 않는다.**

## 진행 체크리스트

매 Task 시작 시:

- [ ] PRD 읽었는가?
- [ ] Task List 다시 확인했는가?
- [ ] 관련 기존 코드 파악했는가?
- [ ] 변경 위치 명확히 정의됐는가?
- [ ] 사용자에게 계획 승인 받았는가?
- [ ] 구현 후 구문 검사 통과했는가?
- [ ] 사용자가 PC에서 테스트 OK 했는가?
- [ ] Implementation Notes에 기록했는가?

## 문제 발생 시 행동

### 1. 디버깅이 30분 이상 걸리면
→ 현재 작업을 더 작은 단위로 분해

### 2. 같은 파일을 3번 이상 수정하면
→ 작업 정의가 잘못된 것. PRD/Task로 돌아가서 재정의

### 3. 기존 기능이 깨지면
→ 즉시 롤백 + 영향 범위 분석 → Task 다시 정의

### 4. 새 의존성이 필요하면
→ 사용자에게 명시적 승인 요청 + PRD에 기록
